# Rust 训练核心移植计划

状态：进行中（2026-11-04）
目标：把《幸运房东》的规则模拟从 Godot 内核迁移到一个只用于训练的高速 Rust 核心，保持 Godot 内核作为标准答案和可视化验证工具。

> 本文是实现过程的验收记录，包含不同阶段的数字快照；最新测试数量、性能和胜率以 [README.md](README.md) 与 [FIDELITY.md](FIDELITY.md) 为准。

## 0. 目标与非目标

### 目标

- 训练模拟器达到每秒至少 100 局（单核），理想是每秒 1000 局以上；20 个逻辑线程并行后，百万局级别的实验可以在分钟到小时级完成。
- 规则保真度可分阶段验收：先覆盖一局的主要经济循环和主流符号，再用差分测试逐步补齐物品、精华、诅咒、房东战和边界规则。
- 提供强化学习需要的环境接口：确定性种子、可变候选动作、合法动作掩码、观察编码、奖励、批量并行。
- 让 Python 训练端（PyTorch/Stable-Baselines3 或自写训练器）通过 PyO3 调用 Rust 核心，训练循环不经过 Godot。

### 非目标

- 不重写 Godot 的 UI、动画、音效和存档。
- 不追求第一版就 100% 复刻全部 168 个符号、114 个物品和 113 个精华。
- 不在 Rust 里实现神经网络训练；Rust 只负责环境，训练仍用 Python/PyTorch。
- 不把大语言模型放进每一步决策循环。

## 1. 机器评估

当前机器：

- CPU：Intel i7-12700F，12 核 20 线程，基准 2.1 GHz。
- 内存：16 GB。
- 显卡：NVIDIA GTX 1650 SUPER，4 GB 显存；另有 MuMu 虚拟显示适配器。
- 软件：Rust 1.99.1、Python 3.12.2、NumPy 2.5.3；PyTorch 尚未安装。

结论：这台机器完全够用。

- 模拟器是 CPU 密集型、状态很小，20 个线程可以并行跑 20 局左右；16 GB 内存足够。
- 4 GB 显存适合小型策略网络（几十万到几百万参数），不适合大模型；这正好符合“小网络 + 大量模拟”的路线。
- 如果后续需要更大的网络，可以用云端 GPU；环境和训练代码不必改。
- 不建议现在买新硬件。先把 Rust 核心和训练闭环跑通，确认瓶颈后再考虑升级。

## 3. 总体架构

```
Python 训练端（PyTorch / Stable-Baselines3 / 自写 PPO）
        │  observation / action / reward
        ▼
PyO3 绑定（lbal_py）
        │
        ▼
Rust 核心（lbal_core）
  ├─ data：JSON 数据加载与名称/分组索引
  ├─ state：牌组、棋盘、物品、金币、租金、代币、房东
  ├─ spin：抽牌/布局、旋转、邻接、数值结算
  ├─ effects：符号/物品/精华效果注册表
  ├─ shop：候选、跳过、重掷、删除、物品、精华
  ├─ run：12 次交租、房东战、输赢判定
  ├─ rng：确定性 PCG，可复现
  └─ env：Gymnasium 风格接口、合法动作、向量化
        │
        ▼
lbal_cli：批量跑局、性能基准、差分测试、数据导出
```

Godot 内核只保留两条用途：

1. 规则标准答案：同种子/同状态差分测试。
2. 可视化和人工检查：需要看画面时用 Godot 跑。

## 4. 规则分层

按“对胜率和训练价值的影响”排序，而不是按符号编号排序。

### 第 0 层：经济与流程骨架（第一版必须）

- 转盘：5 列 × 4 行，共 20 个可见格；从牌组随机排列，空位用空格补齐。
- 基础收入：符号基础值求和。
- 租金序列：25、50、100、150、225、300、375、450、600、650、700、777；第 20 层后 6～10 次各加 25。
- 金币、交租、失败判定、简单的商店/奖励循环。
- 重掷/删除代币的基本消耗。

### 第 1 层：主流符号效果（优先）

先覆盖出现频率最高、对收入影响最大的符号，例如：

- 基础：金币、樱桃、花、猫咪、珍珠、狗狗、啤酒、矮人、矿工、矿石、大矿石。
- 成长：潜水员、地质学家、海盗、鸽子、水果女士、紫水晶、梨。
- 倍率/关联：农夫、厨师、太阳、月亮、蜜蜂、蜂巢、灯泡、贵妇、迈达斯国王。
- 一次性/扭蛋：财富扭蛋、虚空之石、移除扭蛋、重掷扭蛋、物品扭蛋、精华扭蛋、诈骗扭蛋。
- 常见物品：矿镐、墓碑、开锁器、胶囊翻倍、生锈齿轮、绿/紫辣椒、系绳硬币、同花。

### 第 2 层：完整物品、精华、诅咒

- 全部物品和精华的被动/触发效果。
- 诅咒的净收益和触发概率。
- 同花、系绳硬币、金箭头、罗宾汉等组合。
- 交换装置、油罐、枕头等交互。

### 第 3 层：边界与长尾

- fine print 的 37 条数据（真机基础版实际抽取池为 31 条：4 与 8–37）。
- 房东战、Boss 阶段、无限模式。
- 稀有/非常稀有符号的完整效果。
- Mod 相关字段（训练不启用，但数据加载要能忽略）。

## 5. 保真度策略

不能一开始就假设 Rust 和 Godot 完全一致。采用“标准答案 + 差分测试 + 差异清单”的方式：

1. **状态哈希**：每步把牌组、棋盘、金币、租金、代币、物品、房东血量等序列化成稳定哈希。
2. **同种子对照**：用相同种子分别跑 Godot 和 Rust，比较每步状态哈希；第一版允许在未实现规则处出现差异，但必须记录。
3. **分布对照**：对暂时无法逐帧一致的规则，比较 1000 局的租金分布、收入分布、胜率和符号出现频率。
4. **规则清单**：把差异按“影响大/中/小”记录到 `rust/FIDELITY.md`，作为下一阶段移植顺序。
5. **回归门禁**：每次补一批规则，跑固定种子集；已对齐的种子不能回退。

第一版先实现“牌组/棋盘/基础收入/租金”的确定性部分，符号效果先用基础值；这会得到一个偏低的胜率，但能验证速度、接口和工程结构。随后按第 1 层逐步补齐。

## 6. 强化学习接口设计

### 动作

动作不是固定的 4 个按钮，而是一个可变候选集合。建议用“候选打分”而不是固定动作编号：

- 全局状态编码一次。
- 每个候选（符号、物品、删除目标、油罐列、交换位置）编码一次。
- 网络输出每个候选的分数，在合法候选上做 softmax。
- 这样候选数量变化不影响网络结构。

动作类型至少包括：

- 选符号/物品/精华。
- 跳过、重掷。
- 打开删除、选择删除目标、取消删除。
- 选择油罐列、交换两个位置。
- 开关物品。
- 旋转。

### 观察

- 全局标量：租金、已交租次数、金币、剩余旋转、牌组张数、重掷/删除代币、房东血量、当前阶段。
- 棋盘：20 个格子的符号嵌入 + 每个符号的当前值/倍率/加成/是否已消除。
- 牌组：每种符号的数量和特征。
- 物品/精华：类型、是否启用、已保存数值。
- 候选：类型、稀有度、基础值、当前估值、关联标签。

第一版可以用小型多层感知机 + 候选打分；后续再换 Transformer 或图注意力。

### 奖励

- 主奖励：交租成功、最终胜利。
- 辅助奖励：金币/租金进度、余额、收入增长、牌组质量。
- 用势能奖励避免“刷奖励”；不要只用最终输赢，否则一局上百步，信号太稀疏。
- 现有启发式的估值可以作为辅助目标或行为克隆标签，但不要把它当成绝对正确答案。

### 训练顺序

1. **行为克隆**：用现有 18% 基线生成百万级决策，训练候选打分网络模仿；得到一个神经基线。
2. **强化学习微调**：PPO 或 DQN，固定种子集评估；先超过 18%，再冲 30%～50%。
3. **可选**：蒙特卡洛树搜索、价值网络、人类对局、课程学习。

## 7. 性能目标

当前：50 局约 514 秒，约 3～8 秒/局。

> 0.12% 的版本才是与参考 GDScript 一致的规则：猫/矿工/狗等吃取或邻接加成只在本旋生效，慢速符号的周期收益也是临时 `value_bonus`。此前 20.7% 依赖把吃取加成误设为永久，不能作为保真度证据。

最新一版：平均交租 3.83 次、旋转 28.3 次、终局牌组 22.1 张，100,000 局 9,682 局/秒。前 20 旋的收入曲线与真机 v13 基本一致（同一真机对局 spin 20 累计收入 316，Rust 示例 316），差距集中在 225 租金之后：真机 v13 的后期成长依赖精华（`time_machine_essence`、`booster_pack_essence` 等）与更复杂的物品/符文组合，这些尚未在 Rust 中实现，Rust 使用的静态启发式也无法主动搭建成长引擎。因此当前 0.12% 主要反映策略与环境缺失，而不是前中期规则误差。

真实规则版的单核吞吐约 2800 局/秒（20 线程 5.5 万局/秒），仍远高于训练所需；后续加入更多效果会下降，但距离目标仍有余量。

| 阶段 | 单核目标 | 20 线程目标 | 百万局耗时（20 线程） |
|---|---:|---:|---:|
| 第一版骨架 | 10 局/秒 | 150 局/秒 | 约 1.9 小时 |
| 主流规则 | 100 局/秒 | 1500 局/秒 | 约 11 分钟 |
| 完整规则 | 300 局/秒 | 4000 局/秒 | 约 4 分钟 |

第一版先测“纯模拟”吞吐，不包含神经网络推理；训练时的实际吞吐会受策略网络和批量大小影响。

## 8. 里程碑与验收

### M0：工程骨架（已完成）

- Cargo 工作区：`lbal_core`、`lbal_cli`。
- 数据加载：符号、物品、精华、fine print、租金。
- 基础类型、确定性随机数、牌组/棋盘/一局循环。
- CLI 能跑 N 局并输出局数/秒。
- 验收：`cargo test` 通过；CLI 跑 1000 局不崩溃；输出数据数量正确。
- Windows 编译方案：使用 `stable-x86_64-pc-windows-gnu` 工具链，链接器指向工具链自带的 `rust-lld.exe`，已写入 `rust-toolchain.toml` 和 `.cargo/config.toml`；无需安装 Visual Studio。

### M1：经济骨架对齐（已完成第二版）

- 5×4 网格；按列拆分洗牌后的牌组，每列循环显示 4 格；牌组不足 20 时补空位。
- 初始牌组 8 张：金币、樱桃、珍珠、花、猫，加 3 个 Dud；初始金币按真实对局的 1 金再扣首旋 1 金处理为 0。
- 每次旋转后出现普通三选一（初始全普通；付租次数增加后逐步出现非凡、稀有、极稀有）。
- 金币足够即自动支付租金；剩余旋转保留并累加（付租后 +5+floor(付租次数/2)）。
- 付租后依次出现租金符号奖励（1～5 次 3 非凡；6～8 次 1 稀有+2 非凡；9 次 2 稀有+1 非凡；10 次起 3 稀有）和物品三选一。
- 代币：第 3 次付租及之后每次奇数次付租各 +1 重掷、+1 删除。
- 已实现第一批符号效果：相邻倍率（蜜蜂、驯兽师、女巫、贵妇、厨师、农夫、太阳、国王迈达斯）、吞食成长（猫、老鼠、熊、矿工、考古学家、潜水员、海盗、水果女士、矮人、扎罗夫将军、赏金猎人）、钥匙开箱、矿石变宝石、矿山/石巨人/套娃/煤炭计时、牡蛎/鸡蛋/小鸡/母鸡/酒保生成、螃蟹/钻石/西瓜/邪教徒/骰子、礼物/泡泡/灵魂/肥皂自毁、偷窃者死亡收益、胶囊代币和金币。

- 已实现 A20 fine print：仅房东战收入伤害累计 150 点换 3 条（交租前/交租时不产生），可选池为真机基础版 31 条（4 与 8–37），依赖条目/物品的条款记录 dynamic_icon 并只作用于该类型；第 4 条加 Dud、第 14 条加毁灭（毁灭六面体已补上触发效果）；稀有度减半（23）、选项减少（30）、重掷/删除涨价（24/25）、金币/鸡蛋不可删（20/21）、纵向不相邻（22）、概率触发失效（13）、种子不长（34）、矿产不出宝石（15）、宝箱收益降低（9）、宝箱不可毁（10）、扭蛋失效（37）、慢速符号加旋转（12），以及收入修正（26/27/28/29/32/33/35/19）。

## 9. 风险与控制

- **规则保真度风险**：Rust 和 Godot 不一致，策略学到错误规律。控制：差分测试、差异清单、Godot 作为标准答案。
- **过度重写风险**：在模拟器上花太久，训练迟迟不开始。控制：第 0/1 层先跑通，主流规则优先，长尾后补。
- **动作空间风险**：固定动作编号无法处理可变候选。控制：候选打分网络 + 合法动作掩码。
- **奖励设计风险**：辅助奖励被刷。控制：势能奖励、主奖励以交租/胜利为主、定期人工检查。
- **样本效率风险**：从零强化学习太慢。控制：先用行为克隆，再微调。
- **数字口径风险**：群友说的 90%/94% 可能不是同一规则/难度。控制：固定模拟器、固定种子集、置信区间，不直接跨版本比较。
