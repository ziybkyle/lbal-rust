## 阶段 3：同种子逐旋重放（进行中）

Rust 已复刻 BetterLandlord 的字符串种子派生：FNV-1a 哈希后按 `spin_{n}`
派生 `reel` / `effect` / `reel_shuffle` / `effect_shuffle` 独立 PCG32 流；
`--seed-text` 可直接跑真机种子。真机侧用 `RL_TRACE=1` 记录每旋的候选、
棋盘、牌组、物品、逐图标收入与 effect RNG 序列，Rust 侧用
`--replay-actions` 按真机动作重放并逐项对比。

当前验收数据（200 个不重复种子，前 12 旋，共 2,367 旋，v37）：

| 指标 | 一致率 |
| --- | --- |
| 收入 | 96.8% |
| 棋盘 | 97.6% |
| 候选 | 99.6%（2754/2766） |
| 牌组 | 97.7%（4298/4397） |
| 物品 | 99.2%（4363/4397） |
| 前 12 旋无任何首差异的局 | 78.0%（156/200） |

已确认的关键机制：

- 每旋注册顺序为“物品 → raritymod 图标 → 全图标”，注册期的随机参数
  （d3/d5 掷点、seed/beehive/goose 等）会立即消耗 effect 流。
- reroll 物品在注册期就抽定 d3/d5 两个替换点数，条件评估时复用。
- 检查阶段每销毁一个 `tbd` 符号，会重注册“自身 + 8 邻居”以及随后
  “全部图标”；重注册只推进 RNG，效果因 cleaned hash 去重，首个注册的数值生效。

仍存在的主要差异（按首差异排序，详见计划文档第 22 节）：

- 销毁后“重复注册”的 RNG 消耗尚未在 Rust 建模，导致后续骰子/宝石选择错位。
- 矮人/矿工对多个受害者的计数（如 beer 相邻被摧毁时只计 1 个）。
- 宝石稀有度与成员选择、urn→spirit、胶囊类自毁、多 Dud、套娃/椰子/泡泡等
  生成与位移时序。
- 部分小额收入差（胡椒族、快乐时光、台球、幸运七等），多数疑似由上述 RNG
  错位引起。

阶段 3 的验收口径是 200 种子 × 前 12 旋 100% 一致，当前尚未达成。

### 第七轮（2026-11-06）：纠正“跨旋随机流错位”的假设

这一轮先证伪了一个被当成头号原因的假设，再修掉一个确定的规则漏洞。

**1. 随机流不会跨旋累积。** `begin_spin(spin_n)` 每旋用 `spin_{n}` 重新派生
`reel` / `effect` / `reel_shuffle` / `effect_shuffle` 四条流，所以上一旋多抽
或少抽多少次，都不会带到下一旋。这意味着“销毁后重新注册把整条 effect 流
推歪、导致后面所有旋都错”的说法不成立：错位只发生在**同一旋内、且只影响
该旋此后的抽取**。

**2. 按原计划补“销毁后重注册”的随机数，实测没有收益。** 实现了
`replay_destroy_registration`：销毁批次后对“每个被销毁图标的 8 个邻居”和
“全部仍存活图标”各走一遍注册期抽取，放在移除牌组之前（即 `tick_items` 与
生成物结算之前）。200 种子 2,367 旋的结果是四项指标一动不动（收入、棋盘、
牌组、物品逐位相同），seed43 反而多错了一旋。原因就是第 1 条：这一旋的
`effect` 流走到那里已经快用完了，补上的抽取只影响 `tick_items` 和生成物，
而这两处恰恰不是差异来源。代码已回退，不保留半套机制。

**3. 真正修掉的：碎镜少选项只在交租奖励生效。** `roll_symbol_reward`
（交租奖励）扣了碎镜的选项数，`roll_spin_reward`（普通旋后奖励）没扣，
于是持有碎镜时 Rust 给 3 个候选、真机给 2 个。修复后抽出
`shattered_mirror_penalty()` 供两个入口共用：

| 指标（seed42，100 局） | 修复前 v37 | 修复后 v40 |
| --- | --- | --- |
| 候选一致 | 1386/1394 (99.4%) | 1390/1394 (99.7%) |
| 动作异常 | 8 | 6 |
| 有首差异的局 | 17 | 16 |

三个种子合计：候选 2758/2766 (99.71%)、157/200 局无首差异（78.5%）。

**4. 下一步的靶子**（按当前首差异分类，共 43 局）：

- 宝石身份：sapphire↔shiny_pebble、pearl↔emerald、pearl↔dog，3 局。
  怀疑 `pick_group_rarity` 的稀有度掷点或成员抽取与真机的
  `_pick_rarity_weighted_symbol` 不同（真机是"先定稀有度再抽成员"，
  且 `min_rarity` 的升级链、重复注册时的随机序列都可能影响）。
- urn→spirit 时序与多余生成物（多一颗 cherry、多一个 pearl），5 局。
- `missing_offer:item_capsule`：真机给 3 个不同符号的交租奖励，Rust 走了
  `roll_bonus_symbol_offer` 的"同稀有度 3 连"分支（`vec![pick; 3]`），
  给出 3 个西瓜。这一支的触发条件要单独查。
- 矮人/矿工的多受害者计数：一旋内摧毁两格 beer 时 Rust 只计 1 个。
- 收入差 ±1 的 8 局（happy_hour、各色胡椒、pool_ball、lucky_seven、
  quigley、egg_carton、fish_bowl、birdhouse、zaroffs_contract 等），
  多半是上面的状态差引起的连带。

判断：剩下的差异是**逐条规则**问题，不是某个统一的随机流偏移。继续推进的
方式是每个分类做一个受控场景 + 一条回归测试，而不是再找"总病根"。

## 已对齐的规则

### 整局流程

- 初始牌组 8 张：金币、樱桃、珍珠、花、猫，加 3 个 Dud；初始金币 1，每次旋转扣 1 金（真机轨迹中每次 `balance_after = balance_before + 收入 - 1`）。
- 5 列 × 4 行棋盘；牌组按列拆分并在列内循环取 4 格；空位保留。
- 每次旋转后给普通三选一符号奖励；交租的那一旋改为给租金符号奖励（1～5 次三非凡；6～8 次一稀有+两非凡；9 次两稀有+一非凡；10 次起三稀有），随后给物品三选一。
- 租金序列 25/50/100/150/225/300/375/450/600/650/700/777；只在旋转耗尽时交租，交租后剩余旋转 +5+floor(已交租/2)，与真机轨迹一致。
- 第 12 次交租后进入房东战：房东血量 1500，每轮 10 旋，租金 1000/1500/2000…（每次付租再 +500）；每旋按该旋收入扣减房东血量，归零即获胜；付不起租金则失败。交租本身不造成伤害。
- 第 3 次及之后奇数次交租各 +1 重掷、+1 删除代币、+2 精华代币。
- 交租时先把存量精华代币转成等量的“精华三选一”（每个代币一次三选一），按真机顺序先给精华、再给租金符号、最后给交租物品；第 3 次交租获得的代币要到第 4 次交租才结算。
- 第 15、30、45… 旋各加一个 Dud（房东战前）。
- A20 fine print：只有房东战中的收入伤害累计到 150 点才换 3 条（房东战前不产生小字）；可选池为真机的 31 条（4 与 8–37），1/2/3/5/6/7 为真机不会抽取的遗留条目；第 4 条加 Dud，第 14 条加毁灭。

### 经济与数值

- 基础收入来自符号显式 `value` 字段；`values` 只作为效果参数，不再覆盖基础值。
- 被本旋摧毁的符号不计收入（与真机 `check_values` 一致）。
- 不可删除：Dud 始终不可删；金币仅在第 20 条生效时不可删；鸡蛋仅在第 21 条生效时不可删；虚空按第 36 条指定类型不可删。删除 API 与策略层都执行同一判定。
- 收入修正：fine print 26/27/28/29/32/33/35/19；触发修正 8（六面体）、9（宝箱收益）、11（骨灰瓮）、12（慢速符号）、16（取币物品）、17（胡椒）。
- 稀有度修正：fine print 23、hex_of_tedium、lucky_cat/lucky_carrot/golden_carrot。

## 已知差异

### 高影响

- 尚未模拟的 fine print：31（无物品开关系统，视为无操作）。
- 依赖条目的小字（8/9/10/11/12/13/15/17/19/27/33/36/37）会在抽取时记录 dynamic_icon（取牌组/物品中该分组最常见的类型），效果只作用于该类型；同类有多个最高计数时按名称排序取首个，而真机在并列中随机。
- 依赖物品的 fine print（17 胡椒、18 断头台）按持有物品筛选；此前数据加载只接受数组，导致真机的字符串依赖字段被读空，已修复。
- 物品仍缺少部分“逐物品状态”：肥料的生长概率按乘算 ×1.5 近似（真机为在基础概率上追加 +50 点，可能更高）。存钱罐/脏话罐兑现、卡牌盒、堆肥桶、兔子左撇子、神殿、洗碗机精华已实现。

- 其余未实现物品：item_missing（数据占位符）。交换装置物品已按启发式实现：每份每旋做一次贪心交换，把 dog/bee/omelette 的接收者换到增益源旁，使邻接总加成增大；真机的交换还能服务于其他邻接组合。
